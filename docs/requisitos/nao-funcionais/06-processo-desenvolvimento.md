### RNF12 — Controle de versão

**Situação:** validado.

**Descrição:** versionar código e documentação no repositório compartilhado da equipe.

**Critérios de verificação:**

- Utilizar o repositório `github.com/samuel-0v/pdm-ahp-topsis` para código e documentação.
- Registrar alterações relevantes em commits com mensagens que identifiquem seu propósito.
- Cada integrante utiliza o repositório conforme suas responsabilidades, sem quantidade mínima de commits.
- Identificar por tag cada versão entregue ao professor, permitindo recuperar exatamente o conteúdo apresentado.
- Documentar a configuração dos arquivos necessários com instruções ou exemplos; excluir credenciais administrativas, arquivos locais de ambiente e artefatos gerados.
- Seguir o fluxo aprovado na DEC-031: branch e PR para código e alterações relevantes de requisitos ou arquitetura; commit direto permitido para pequenas correções de texto; revisão por outro integrante antes da integração, quando disponível.

**Método de verificação:** inspecionar histórico, arquivos versionados, tags de entrega e aplicação do fluxo de colaboração. Esta aprovação não declara criação de tags ou PRs.

### RNF13 — Gestão das atividades

**Situação:** validado.

**Descrição:** acompanhar tarefas no GitHub Projects, conforme DEC-031.

**Critérios de verificação:**

- Cada tarefa tem título, descrição e critério de conclusão.
- Tarefas assumidas têm responsável.
- O quadro usa os estados **A fazer**, **Em andamento** e **Concluído**.
- Cada integrante atualiza suas tarefas ao iniciar ou concluir o trabalho.
- Pendências e tarefas necessárias às entregas ficam registradas no quadro.
- Sprints, estimativas em pontos e automações não são obrigatórios.

**Método de verificação:** consulta ao quadro e à situação das tarefas. A escolha da ferramenta não significa que o quadro já tenha sido criado ou configurado.
